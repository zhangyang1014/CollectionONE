## 📋 问题修复时间线

### 2025-11-25: 字段格式统一修复

#### 问题描述
前端代码期望所有API返回的字段名使用**下划线格式（snake_case）**，但Java后端很多Controller返回的是**驼峰格式（camelCase）**，导致前端无法正确读取字段数据。

#### 影响范围
- 字段映射配置页面 - 显示"没有字段内容"
- 字段分组管理页面 - 分组信息显示异常
- 标准字段管理页面 - 字段数据无法显示
- 自定义字段管理页面 - 字段数据无法显示
- 甲方管理页面 - 甲方信息显示异常

#### 修复内容

**修复的Controller**:
1. `StandardFieldController` - 所有方法已修复
2. `CustomFieldController` - 所有方法已修复
3. `FieldGroupController` - 所有方法已修复
4. `TenantController` - 所有方法已修复

**修复的字段**:
- `fieldKey` → `field_key`
- `fieldName` → `field_name`
- `fieldNameEn` → `field_name_en`
- `fieldType` → `field_type`
- `fieldGroupId` → `field_group_id`
- `isRequired` → `is_required`
- `isExtended` → `is_extended`
- `exampleValue` → `example_value`
- `sortOrder` → `sort_order`
- `isActive` → `is_active`
- `tenantCode` → `tenant_code`
- `tenantName` → `tenant_name`
- `countryCode` → `country_code`
- `currencyCode` → `currency_code`
- `groupKey` → `group_key`
- `groupName` → `group_name`
- `parentId` → `parent_id`（或不设置）
- `createdAt` → `created_at`
- `updatedAt` → `updated_at`

#### 测试结果
- ✅ `/api/v1/standard-fields` - 格式正确
- ✅ `/api/v1/field-groups` - 格式正确
- ✅ `/api/v1/tenants` - 格式正确
- ✅ `/api/v1/custom-fields` - 格式正确

### 2025-11-25: parent_id字段类型修复

#### 问题描述
后端返回的 `parent_id` 为 `null`，但前端类型定义为 `parent_id?: number`（`number | undefined`），类型不一致。

#### 修复内容
- 一级分组的 `parent_id` 字段不设置（undefined），而不是设置为 `null`

#### 修复前
```java
group.put("parent_id", null);  // ❌ 错误
```

#### 修复后
```java
// ✅ 正确：不设置parent_id字段（一级分组）
// parent_id不设置，表示一级分组
```

## 🔍 问题根因分析

### 根因1: 缺乏统一的开发规范

**问题**: 没有明确的字段格式规范，导致前后端格式不一致。

**解决方案**: 
- 制定统一的字段格式规范（下划线格式）
- 创建开发规范文档
- 建立代码审查检查点

### 根因2: 接口实现不完整

**问题**: 前端开发时假设后端接口已实现，但实际未实现。

**解决方案**:
- 建立接口清单
- 开发前检查接口完整性
- 使用Mock数据快速实现接口

### 根因3: 缺乏自动化检查

**问题**: 依赖人工检查，容易遗漏。

**解决方案**:
- 创建自动化检查脚本
- 集成到CI/CD流程
- 使用grep检查字段格式
