**修复日期**: 2025-11-25  
**状态**: ✅ 已完成

---

## 📋 问题概述

前端代码期望所有API返回的字段名使用**下划线格式（snake_case）**，但Java后端很多Controller返回的是**驼峰格式（camelCase）**，导致前端无法正确读取字段数据。

### 问题表现
- 字段映射配置页面显示"没有字段内容"
- 表格列无法显示数据
- 字段名称、字段标识等属性无法读取

```bash
cd backend-java
```


## 🎯 修复原则

### 1. 统一使用下划线格式
- **所有API返回的字段名**必须使用下划线格式（snake_case）
- **所有API接收的字段名**可以兼容两种格式（下划线优先，驼峰作为备选）

### 2. 兼容性处理
在接收请求参数时，同时支持两种格式：
```java
field.put("field_key", request.get("field_key") != null ? 
    request.get("field_key") : request.get("fieldKey"));
```

### 3. 前端期望格式
前端代码中大量使用下划线格式：
- `row.field_name`
- `row.field_key`
- `row.field_type`
- `row.is_required`
- `row.sort_order`

## 📝 注意事项

### 1. 新接口开发规范
创建新接口时，**必须**使用下划线格式：
```java
// ✅ 正确
field.put("field_name", "字段名称");
field.put("field_key", "field_key");

// ❌ 错误
field.put("fieldName", "字段名称");
field.put("fieldKey", "field_key");
```

### 2. 请求参数兼容性
接收请求参数时，可以兼容两种格式：
```java
// 优先使用下划线格式，如果没有则使用驼峰格式
String fieldName = request.get("field_name") != null ? 
    request.get("field_name").toString() : 
    (request.get("fieldName") != null ? request.get("fieldName").toString() : null);
```

### 3. 响应数据格式
**响应数据必须统一使用下划线格式**，确保前端能正确读取。
